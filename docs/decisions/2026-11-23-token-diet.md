# 개발 과정 토큰 줄이기 (2026-11-23)

## 왜
photo-video-manager 에서 대화 기록을 집계해 토큰을 줄인 방법(그 저장소 `docs/개발-토큰-점검-가이드.md`)을 이 저장소에도 적용한다. 짐작하지 않고 이 저장소의 대화 기록을 직접 집계한 숫자로 처방을 골랐다.

## 무엇을 쟀나
이 저장소의 Claude Code 대화 기록 15개(턴 543개)를 가이드 9절 스크립트로 집계. 토큰은 API 요금 비율(캐시 읽기 0.1 · 캐시 쓰기 1.25 · 출력 5 · 입력 1)로 가중한 어림값이라 요금제 한도 계산과 정확히 같지는 않다.

| 어디서 | 몫 |
|---|---|
| 캐시 읽기 = 말할 때마다 대화 전체를 다시 읽는 값 | **60%** |
| 캐시 쓰기 (새로 올린 내용) | 21% (10만 넘게 통째로 다시 올린 일은 0%) |
| 출력 (Claude 가 쓴 글 · 코드) | 19% |
| 대화가 20만 토큰을 넘은 턴에서 나온 비용 (200~400k 33% + 400k 넘음 13%) | **46%** |
| 가장 비싼 메인 세션 1개 (메시지 208개, 최대 대화 약 50만 토큰) | **46%** |
| 에이전트(검증 · 조사) 전체 | **22%** |
| 세션 시작 바탕 중간값 약 8.5만 토큰을 턴마다 다시 읽는 값 | 약 28% |

대화에 들어간 도구 결과는 셸 파일 읽기 41만 자 · WebFetch 37만 자 · Read 25만 자 · WebSearch 12만 자 순이고, 같은 파일을 10번 넘게 읽은 일은 없었다 (최대 4번). 테스트 출력 6만 자, 훅이 다시 쓰게 한 일 0번.

## 판정 (가이드 2절 표)
| 볼 것 | 이 저장소 값 | 기준 | 처방 |
|---|---|---|---|
| 200k 넘는 칸 합계 | 46% | 30% 넘음 | ① 대화 길이 상한 → **적용** |
| 상위 세션 메시지 수 · 최대 대화 | 208개 · 약 50만 | 300개 · 50만 넘음 | ② 주제마다 새 세션 → 기준에는 못 미치지만 최대 대화가 기준 바로 아래이고 비용 없는 규칙이라 **적용** |
| 세션 시작 바탕 | 약 8.5만 | 6만 넘음 | ③ 안 쓰는 플러그인 · 연결 도구 끄기 → **적용** |
| 같은 큰 파일 다시 읽기 | 최대 4번 | 10번 넘음 | ④ 큰 파일 부분 읽기 → 해당 없음 |
| 에이전트 몫 | 22% | 15% 넘음 | ⑤ 검증은 바뀐 줄만 + 싼 모델 → **적용** |
| 테스트 · 훅 | 테스트 출력 6만 자 · 훅 0번 | 작음 | 손대지 않음 |

## 고른 처방
1. **대화 길이 상한 20만 토큰**: `.claude/settings.json` 에 `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000`. 비용의 46% 가 20만 넘는 턴에서 나왔으므로 1순위
2. **주제마다 새 세션**: 가장 비싼 세션 하나가 수집처 추가와 수집 기준 설정을 한 대화에서 이어 가며 전체의 46% 를 썼다. 메인은 15만 토큰을 넘으면 하던 PR 끝에 넘긴다
3. **시작 바탕 줄이기**: 이 저장소 기록에서 한 번도 쓰지 않은 플러그인 4개(adhd-study-coach · pdf-viewer · code-simplifier · learn-with-coursera)를 프로젝트 설정에서 끔. 계정 연결 도구(Canva · Figma · Notion · Google Drive · Docs)도 이 저장소에서는 호출 0번이라, 사용자가 앱에서 끄면 바탕이 더 줄어든다 (저장소 설정으로는 못 끔. 다른 프로젝트에서 쓰는 것은 세션마다 끄는 쪽이 낫다)
4. **검증 에이전트는 바뀐 줄만 + Sonnet**: 큰 위험(규칙 · 설정, 워크플로, 보낸 공고 기록 · 발송, 삭제)만 전체 검증 + Opus

## 그대로 둔 것
- **superpowers**: 기록에서 스킬을 15번 불렀고(설계 · 계획 · 실행 · TDD · 마무리), `docs/superpowers/` 의 계획 · 설계 문서가 이 저장소의 진행 기록 역할을 한다
- **code-review 플러그인**: 쓰지는 않았지만 독립 검증에 쓸 수 있어 남김
- 큰 위험 변경의 전체 검증 · 사용자 "머지" 승인

## 버린 안
- **④ 큰 파일 부분 읽기 규칙**: 파일 읽기 결과(셸 41만 자 + Read 25만 자)가 도구 결과 중 크긴 하지만, 같은 파일을 10번 넘게 읽은 일이 없어(최대 4번) 가이드 기준에 못 미쳐 이번엔 넣지 않음
- **조사(WebFetch · WebSearch) 줄이기**: 합쳐 49만 자로 도구 결과 중 크지만, 수집처 조사가 끝난 초기 단계의 일이라 앞으로 줄어들 것으로 봄

## 확인할 것
- 머지 뒤 새 세션에서 `get_usage` 로 자동 요약 기준이 20만 근처로 바뀌었는지, 세션 시작 바탕이 8.5만 토큰보다 줄었는지 본다. 프로젝트 설정의 `env` 는 폴더를 신뢰한 뒤에 적용되므로, 안 바뀌면 같은 값을 사용자 설정에 넣을지 정한다
- 꺼 둔 플러그인 4개는 claude.ai 에서 동기화된 플러그인이라 `이름@마켓플레이스` 키가 먹는지 아직 확인하지 못했다. 새 세션의 스킬 · 에이전트 목록에서 빠졌는지 본다
- 1~2주 뒤 같은 스크립트를 다시 돌려 200k 넘는 칸(지금 46%)이 줄었는지 비교
