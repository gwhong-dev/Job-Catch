# 필수조건 · 카드 채우기 · 통근순 정렬 설계

작성일: 2026-11-23 · 앞 설계: `2026-11-23-summary-groups-design.md`

## 왜

사용자는 아침 메일에서 카드 한 장만 보고 "열어 볼지"를 정한다. 판단 순서는

1. **거리(통근)**: 멀면 지원을 망설인다. 가장 먼저 본다.
2. **하는 일 · 쓰는 기술** (📝 요약 · 태그)
3. **필수조건**: 있으면 참고. 어떤 조건이 걸림돌인지는 아직 데이터가 쌓이지 않았다.

그래서 손이 먼저 가는 카드는 "정확한 주소 · 통근 시간 · 요약 · 태그"가 다 있는 카드다. 11/23 dry-run(카드 65장)에서 이런 카드는 27장뿐이었다.

- 17장: 상세 조회 상한(60건)에 걸려 본문을 안 읽음 → 주소가 "서울 금천구" 수준, 요약 · 통근 없음. 갈래 순서대로 처리해서 뒤쪽 갈래(개발 전환)만 몰려서 굶었다. 이 공고는 보낸 기록에 남아 다음 날에도 다시 읽지 않는다.
- 21장: 본문을 읽었지만 요약이 비었다 (이미지 공고, 제목을 못 찾음).
- 요약이 있어도 틀린 것: "및" 한 단어, 회사 소개 문장("[채용 기업] / 채용기업은 미국 나스닥에…"), 사이트 양식 잔재("상세내용을 입력하세요"), 제목이 섞임("주요업무 / 담당업무 / …"), 문장 중간부터("까지 함께할 엔지니어를 찾습니다").

## 목표

- 메일에 실리는 카드가 가능한 한 모두 상세 본문을 읽은 카드가 되게 한다.
- 묶음 안에서 통근이 짧은 공고가 위로 온다.
- 카드에 필수조건 한 줄을 보여 준다 (본문 글자에서 뽑을 수 있을 때).
- 틀린 요약은 보여 주지 않는다 (틀린 것보다 빈 것이 낫다).
- 나중에 추출 방법을 무료 AI 모델(방법 2)로 바꿀 수 있게, 추출을 한 곳에 모은다.

## 하지 않을 것 (non-goals)

- 내 역량과 필수조건을 맞춰 보는 점수 · 판정 · 제외. 데이터가 쌓인 뒤에 정한다.
- 우대조건 추출.
- 이미지 공고 OCR. 방법 2로 바꾸면 AI 가 이미지도 읽으므로 지금 만들지 않는다.
- 무료 AI 모델 연동 자체 (다음 설계).
- 같은 회사의 반복 공고 묶기, 태그 오탐 전반 손보기.

## 실패로 치는 것 (anti-goals)

- 필수조건을 잘못 읽어 맞는 공고가 메일에서 빠지는 것. 필수조건은 **보여 주기만** 한다.
- 공개 실행 로그에 공고 제목 · 본문 · 설정 내용이 찍히는 것. 로그에는 건수만.
- 사이트에 과한 요청 (요청 사이 `delay_sec` 대기는 유지).

## 고른 방법

- **방법 1. 규칙 방식 넓히기 — 사용자 선택.** 본문을 제목 기준 구역으로 나눠 업무 요약과 필수조건을 같은 파서에서 뽑고, 엉터리 요약 거르기 규칙을 더한다. 무료 · 새 키 없음 · 테스트 쉬움. 처음 보는 공고 양식에는 약하다.
- 방법 2. 무료 AI 모델(GitHub Models, Gemini 무료 한도 등)에 본문 · 이미지를 보내 요약 · 필수조건을 받기. 품질이 가장 좋고 이미지도 해결되지만, 무료 한도 · 약관 변동, 외부 의존, 키 관리가 늘어난다.
- 방법 3. 규칙 먼저, 실패한 공고만 AI. 호출이 적지만 가장 복잡하다.

사용자 결정: **방법 1로 메일을 두세 번 받아 본 뒤 방법 2로 바꿔 본다.** 그래서 이번 작업은 방법 1을 만들되, 추출 결과를 한 함수 · 한 자료형으로 모아 나중에 통째로 갈아 끼울 수 있게 한다.

## 동작

### 1. 상세 조회 상한 · 다시 읽기 · 갈래 공평

- `max_detail_lookups` 기본값을 60 → **150** 으로 올린다. 예시 설정 · README 의 "하루 최대 60건" 문구도 고친다.
- **시간 안전장치**: 잡코리아는 상세 1건에 요청 2번 · 대기 2번이라 1건에 5~6초, 150건이면 12~15분이다. 상세 조회 단계가 **15분**을 넘으면 거기서 멈추고, 남은 공고는 상한에 걸린 것과 똑같이 처리한다. 워크플로 제한(30분)은 그대로 둔다. (설계자 결정)
- 상세 조회 순서: **마감 7일 안 공고를 먼저**, 그다음 **갈래별로 번갈아** (갈래 A 1건 → 갈래 B 1건 → …). 마감 임박 카드에도 주소 · 요약이 붙고, 한 갈래가 상한을 다 쓰지 않게 하려는 것이다. (마감 임박 먼저는 설계자 결정)
- **상한에 걸린 공고는 오늘 메일에 싣지 않고, 보낸 기록에도 남기지 않는다.** 다음 실행에서 다시 후보가 되어 상세를 읽는다.
  - 예외: 마감이 7일(`CLOSING_DAYS`) 안이면 지금처럼 지역 목록 판정으로 싣는다 (기다리면 놓친다).
  - 다음 날 검색 결과(검색어당 2페이지)에서 밀려나면 그 공고는 영영 안 온다. 상한을 넉넉히 올려 드물게 만드는 것으로 감수한다.
  - 미룬 공고를 다음 날 먼저 읽게 하는 별도 기록(`seen.json` 의 "미룸" 상태)은 만들지 않는다. 다음 날에는 새 후보와 같은 순서로 다시 줄을 선다. 로그의 미룸 건수가 며칠 계속 크면 그때 더한다. (설계자 결정)
- **상세 조회 실패**(요청 오류 · 빈 응답)는 미루지 않고 지금처럼 지역 목록 판정으로 싣는다. 미루면 사이트 구조가 바뀌었을 때 공고가 조용히 사라지기 때문이다. 대신 한 사이트에서 상세 조회가 3건 이상 시도되고 그 절반 이상이 실패하면, 메일 맨 위에 "상세 페이지 읽기 실패" 경고를 띄운다 (지금의 수집 실패 경고와 같은 자리). (설계자 결정)
- 실행 로그에 "상세 조회 상한으로 N건은 내일 다시" 를 건수만 남긴다 (지금의 `unchecked_by_cap` 안내를 바꾼다).

### 2. 묶음 안 순서: 통근 짧은 순

- 갈래 → 묶음 순서는 그대로 (설정 순서, "기타" 맨 뒤).
- 묶음 안: **통근 시간 짧은 순 → 통근 모름은 뒤 → 같으면 마감 빠른 순 → 제목.**
- 카드 상한(`max_cards_per_track`)은 지금처럼 정렬 뒤 뒤쪽부터 자른다 (뒤쪽 묶음, 묶음 안에서는 먼 공고부터 잘린다).
- 마감 임박 칸은 지금처럼 마감순.

### 3. 본문 구역 나누기 → 업무 요약 · 필수조건 · 태그

추출을 `analyze(body, extra_tags) -> Analysis(duty, required, tags)` 한 곳으로 모은다 (`jobcatch/summary.py`). `digest.py` 는 이 결과만 쓴다. 방법 2로 바꿀 때 이 함수의 안쪽만 갈아 끼운다.

- **구역 나누기**: 본문에서 제목 줄을 찾아 "업무 / 필수 / 우대 / 기타(근무조건 · 복지 · 전형 · 회사소개 …)" 구역으로 나눈다.
  - 제목은 **줄 맨 앞**(글머리표 · 괄호 · 번호 다음)에 와야 인정한다. 문장 중간의 "하는 일" 같은 말에 걸리지 않게 하려는 것이다.
  - 회사 소개("[채용 기업]", "회사 소개", "기업 소개" 등)도 구역 제목으로 인식해, 업무 구역에 섞이지 않게 한다.
- **업무 요약(📝)**: 업무 구역의 항목을 ` / ` 로 이어 붙인다. 지금 방식 그대로이고, 아래 거르기를 통과한 것만 쓴다.
- **필수조건(✅ 필수)**: "자격요건 / 지원자격 / 필수요건 / 자격조건" 계열 구역의 항목. 그 안에 "우대" 소제목이나 "우대"로 시작하는 항목이 나오면 거기서 멈추거나 그 항목을 뺀다. 우대조건만 있는 공고는 필수조건을 비운다.
- **거르기 (요약 · 필수조건 공통)**
  - 항목에서 제목 말("주요업무", "담당업무" 등)만 있는 조각, 사이트 양식 잔재("상세내용을 입력하세요" 등)를 뺀다.
  - 남은 글이 너무 짧거나(예: "및"), 뜻 있는 낱말이 없으면 통째로 비운다.
- **태그**: 업무 · 필수 구역을 찾았으면 그 구역 글에서만 찾는다. 못 찾았으면 지금처럼 본문 전체에서 찾는다. 여러 직무를 한꺼번에 뽑는 공채에 태그가 6개씩 붙는 것을 줄이려는 것이다.
- 이미지 공고 등 본문 글자가 없으면 세 값 모두 비운다.

### 4. 메일 카드

```
D-27 · ㈜서울소프트 [잡코리아]
[서울소프트(가산)] 풀스택 개발자 (신입·경력)
📍 서울 금천구 가산디지털1로 84 … · 🚇 약 60분
📝 웹 서비스 개발 및 유지보수 / 백엔드 API 설계 및 개발 / …
✅ 필수: 초대졸 이상 / Java 또는 Python 경험 / …
[Java] [Python] [MySQL]
공고 보기 →
```

- 📝 다음 줄에 `✅ 필수: …`. 비어 있으면 줄을 그리지 않는다.
- 마감 임박 카드(`ClosingItem`)에도 같은 줄을 넣는다.

### 4-1. 마감 임박 다시 알림 카드도 채우기

지금은 예전에 보낸 공고를 마감 7일 전에 다시 알릴 때, 보낸 기록(`seen.json`)에 제목 · 회사 · 링크 · 마감일만 있어서 주소 · 요약 · 확인 표시가 다 빠진 카드가 나온다. 사용자가 "지역이 안 나오는데 걸러진 게 맞나" 헷갈려 했다.

- 보낸 기록 `Entry` 에 **주소(없으면 목록의 지역), 업무 요약, 필수조건, 태그, 확인 표시(학력 확인 등)** 를 더 저장한다.
- **통근 시간은 저장하지 않는다** (집 위치를 짐작할 수 있는 값이라 지금 원칙 유지). 다시 알릴 때 카카오가 켜져 있고 주소가 있으면 그 자리에서 다시 계산한다. 못 구하면 통근 없이 싣는다.
- 예전 형식 기록(새 칸 없음)은 그대로 읽고, 지금처럼 빈 카드로 싣는다. 새로 보내는 공고부터 채워진다.
- 상세 조회 뒤 제외된 공고 기록(`excluded`)에는 새 칸을 채우지 않아도 된다.

### 5. 실행 로그 (건수만)

방법 2로 바꿀지 판단하는 재료로, 실행마다 다음 건수를 남긴다: 상세 읽음 N · 상세 실패 N · 요약 있음 N · 필수조건 있음 N · 상한(시간 포함)으로 미룸 N. 공고 제목 · 본문은 찍지 않는다.

## 테스트로 꼭 지킬 것

11/23 dry-run 에서 본 실패를 (회사 · 공고를 알아볼 수 없게 바꾼) 짧은 본문 조각으로 테스트에 넣는다.

- "및" 한 단어 요약 → 빈 요약
- 회사 소개 구역이 업무 구역보다 먼저 나오는 본문 → 회사 소개가 요약에 안 들어감
- "상세내용을 입력하세요" 반복 → 잔재가 빠짐
- "주요업무 / 담당업무 / …" 처럼 제목 두 개가 이어짐 → 제목 조각이 빠짐
- 문장 중간의 "하는 일" → 제목으로 인식하지 않음
- 자격요건 안에 우대 항목이 섞임 → 필수조건에 우대가 안 들어감
- 상한에 걸린 공고 → 메일 · 보낸 기록에서 빠지고, 마감 7일 안이면 실림
- 시간 안전장치에 걸린 공고 → 상한과 똑같이 처리
- 갈래 두 개 · 상한 작게 → 두 갈래 모두 상세를 읽음, 마감 임박 공고가 먼저 읽힘
- 상세 조회 실패 → 지역 판정으로 실림, 실패가 절반 이상이면 경고
- 묶음 안 정렬: 통근 30분 · 50분 · 모름 순
- 보낸 기록 저장 → 불러오기 → 마감 임박 다시 알림 카드에 주소 · 요약 · 필수조건 · 태그 · 확인 표시가 나옴, 통근은 기록 파일에 없음
- 예전 형식 기록 → 오류 없이 읽히고 빈 카드로 실림

## 만드는 사람에게 맡기는 것

- 구역 제목 단어 목록, "너무 짧다"의 기준, 잔재 문구 목록.
- 요약 · 필수조건 자르기 길이와 방식 (지금 80자. 항목 경계에서 자르는 쪽이 좋다).
- 잡코리아 상세에 "스킬" 같은 정해진 칸이 있으면 태그에 먼저 쓰기 (있을 때만).
- 갈래 번갈아 처리를 수집 순서로 할지 상세 조회 단계에서 할지.
