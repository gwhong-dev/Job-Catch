# 세부 분류 · 공고 요약 설계 (작은 변경)

작성일: 2026-11-23 · 앞 설계: `2026-11-22-jobkorea-daily-email-design.md`

## 왜

첫 메일(새 공고 62건)이 갈래 안에서 한 줄로 길게 이어져 훑기 어렵다. 사용자는 갈래 안을 기구설계 / 장비설계 / 설비설계처럼 나눠 보고, 카드마다 **공고명 · 지역(근무지 주소) · 공고 내용 요약(예: 컨베이어 설계 / Creo 사용)** 을 보고 싶어 한다.

## 고른 방법

- 요약: **A. 규칙으로 뽑기 (무료) — 사용자 선택.** 상세 본문의 "주요업무/담당업무" 첫 부분 + 정해 둔 단어 목록(툴 · 분야)에서 걸리는 태그.
- B. Claude API 요약은 유료라 보류. 며칠 받아 보고 부족하면 추가한다.
- 본문을 이미지로만 올린 공고는 요약 없이 표시만 한다 (OCR 하지 않음).

## 동작

1. 상세 본문 읽기 (처음 보는 후보만, 하루 `max_detail_lookups` 상한, 요청 사이 `delay_sec`)
   - 사람인: `/zf_user/jobs/relay/view-detail?rec_idx=<id>` (본문, 15KB 내외). 본문의 "근무지 : …" 줄을 주소로 쓰고, 없으면 기존 `/zf_user/jobs/view` 에서 주소 · 좌표.
   - 잡코리아: 기존 `GI_Read/<id>` (주소 · 학력 · 마감) + `GI_Read_Comt_Ifrm?Gno=<id>` (본문).
   - 통근 계산 여부와 상관없이 본문을 읽는다 (요약에 필요).
2. 요약: 본문에서 "주요업무 / 담당업무 / 업무내용" 다음부터 다음 제목(자격요건 · 우대 · 근무조건 · 복지 · 전형 등) 전까지, 글머리표를 ` / ` 로 이어 80자까지.
3. 태그: 기본 단어 목록(설계 툴 · 분야 · 개발 기술) + 설정 `[common] extra_tags` 에서 걸리는 것, 최대 6개.
4. 세부 묶음: 갈래 설정 `groups = { "기구설계" = ["기구"], … }` 순서대로 제목 · 직무 태그에 단어가 있으면 그 묶음, 없으면 "기타". `groups` 가 없으면 묶지 않는다.
5. 메일
   - 맨 위 목차: 갈래별 건수와 묶음별 건수 한 줄씩.
   - 갈래 → 묶음 소제목 → 카드. 카드 상한(`max_cards_per_track`)은 갈래 단위 그대로, 묶음 순서 · 마감일 순으로 정렬해서 "기타" 가 먼저 잘린다.
   - 카드: `D-14 · 회사 [사람인]` / 제목(경력) / `📍 근무지 주소 · 🚇 약 52분` / `📝 요약` / 태그 · 확인 표시 / `공고 보기 →`. 고용형태 · 학력 줄은 뺀다 (이미 걸러진 값).

## 하지 않을 것

- 이미지 공고 OCR, 유료 요약.
- 묶음을 사이트 직무 분류 코드로 나누기 (제목 단어로 충분하다고 봄).

## 만드는 사람에게 맡기는 것

- 기본 태그 목록의 구체 단어, 본문 제목 인식 패턴, 80자 자르기 방식.
- 워크플로 `timeout-minutes` 를 상세 요청 증가에 맞게 늘리기.
