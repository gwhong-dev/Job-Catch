# 잡코리아 수집 · 통합 검색 기준 · 매일 아침 메일 설계

작성일: 2026-11-22

## 1. 왜 만드는가

구직자가 사람인과 잡코리아에서 자기 조건에 맞는 새 공고만 골라, 매일 아침 휴대폰으로 메일 한 통을 받게 한다. 메일에서 요약을 보고 링크를 눌러 원문 사이트에서 지원한다.

처음 쓰는 사람은 저장소 주인 본인이지만, **포트폴리오로 공개하고 다른 사람도 자기 저장소로 가져가(fork) 쓸 수 있게** 만든다. 그래서 프로그램과 개인의 검색 기준을 분리한다.

대표 사용 예 (기본 예시 설정의 근거):
- 한 분야 경력자가 두 갈래로 지원한다
  - **같은 분야 갈래**: 기존 경력 직무 — 신입 또는 경력
  - **직무 전환 갈래**: 다른 분야 — 신입으로 지원
- 갈래마다 잘 맞는 사이트가 다를 수 있다 (예: 설계 직무는 사람인, IT 개발은 잡코리아)

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

목표
- 잡코리아 검색 페이지 수집기 추가 (사람인 수집기와 같은 `Job` 형태로 반환)
- 검색 기준을 "공통 조건 + 갈래별 검색" 한 설정으로 적는다
- 매일 06:30 KST 실행 → 7시 전후 Gmail 로 본인에게 HTML 메일 발송 (GitHub Actions)
- 이미 보낸 공고는 새 공고로 다시 보내지 않음
- 다른 사람이 fork → 설정 4개 등록 → Actions 켜기만으로 쓸 수 있게 README 안내

하지 않을 것
- 자동 지원, 로그인이 필요한 페이지 접근
- 지도 API 로 실제 통근 시간 계산 (1차는 지역 목록으로 대신함)
- 공고 상세 내용 요약 · 매칭 점수 (README 2단계)
- 여러 사람에게 보내는 서비스 운영 (각자 자기 저장소에서 자기에게만 보냄)

실패로 보는 것 (동작은 해도)
- 조건과 무관한 공고가 많아 메일을 안 읽게 되는 것
- 수집이 막혔는데 아무 알림 없이 "새 공고 0건"처럼 보이는 것
- 개인 검색 기준(학력 · 경력 · 지역 · 직무)이나 비밀값, 또는 그것을 짐작할 수 있는 수집 결과가 공개 저장소 · 공개 실행 로그에 남는 것

## 3. 제약

- 저장소 `gwhong-dev/Job-Catch` 는 **공개**로 유지한다. 공개 저장소의 Actions 실행 로그는 누구나 볼 수 있다.
- 사이트 부담: 하루 1회, 검색 조건당 최대 2페이지, 요청 사이 2초 이상 대기 (기존 원칙 유지)
- 사람인 · 잡코리아 robots.txt 는 일반 접속(`User-agent: *`)에 검색 페이지를 막지 않는다 (2026-11-22 확인). 잡코리아는 `/Recruit/JobList/SpaceClick` 만 막는다.
- GitHub Actions 해외 IP 를 사이트가 막을 수 있다. 막히면 실행 위치를 PC 의 Windows 작업 스케줄러로 옮긴다 (코드는 같음, 이번 범위 밖).
- 무료: Gmail SMTP(앱 비밀번호), GitHub Actions(공개 저장소 무료)

## 4. 검토한 방법과 고른 것

실행 위치
- **A. GitHub Actions — 고름.** PC 가 꺼져 있어도 돈다. 해외 IP 차단 위험이 있어 처음에 실제로 돌려 확인한다.
- B. Windows 작업 스케줄러: 차단 걱정은 없지만 아침에 PC 가 켜져 있어야 한다. A 가 막히면 B 로.
- Claude 예약 작업: 사용량이 들고 이 일에는 필요 없어 제외.

개인 기준을 둘 곳
- **공개 저장소 + 기준은 Actions Secret — 고름 (최종 검토 뒤 변경).** 저장소에는 `config.example.toml` 만. 원본은 각자 PC 의 `config.toml` 에 두고 고칠 때마다 Secret 을 통째로 덮어쓴다.
- 공개 저장소 + 기준을 Variable 에: 처음에 골랐으나, Actions 가 step 의 `env:` 값을 공개 실행 로그에 펼쳐 보이며 Variable 은 가려지지 않아 제외.
- 저장소 비공개: 가장 간단하지만 포트폴리오 · 공유 목적과 맞지 않아 제외.

통근 기준 (2026-11-22 사용자 요청으로 변경)
- **상세 페이지 근무지 주소 + 카카오 대중교통 시간 — 고름.** 처음 보는 후보 공고만 상세 페이지에서 도로명 주소를 읽고, 카카오 로컬 API로 좌표를 구한 뒤, 카카오맵 대중교통 경로 조회로 집→근무지 시간을 구한다. 카카오 키 하나(무료: 대중교통 하루 1,000건, 주소 변환 하루 100,000건, 심사 없음). 자차 기준은 이번에 넣지 않는다 (카카오모빌리티 길찾기는 권한 신청 필요).
- 지역 목록: 카카오 키나 집 주소가 없을 때, 또는 주소 · 경로를 못 구한 공고에 쓰는 예비 기준으로 남긴다.
- ODsay: 하루 1,000건 무료지만 서버 IP 등록이 필요해 매번 IP가 바뀌는 GitHub Actions와 맞지 않아 제외.

검색 기준 구조
- **공통 조건 + 갈래(track)별 검색, 갈래마다 사용할 사이트 지정 — 고름.** 나중에 한 줄로 사이트를 더할 수 있다.
- 사이트별 블록에 코드 직접 기입: 공통 조건을 두 번 적어야 해서 제외.

## 5. 설정

### 읽는 순서
1. 환경변수 `JOBCATCH_CONFIG` (TOML 전문) — Actions 에서는 Secret `JOBCATCH_CONFIG` 를 넣어 준다
2. 없으면 저장소 폴더의 `config.toml` (`.gitignore` 에 추가 — 로컬 실행용, 커밋 안 함)
3. 둘 다 없으면 오류로 멈춘다 (`config.example.toml` 을 복사하라고 안내)

### 모양 (`config.example.toml`, 커밋됨)

사람이 읽는 말로 적고, 사이트 코드로 바꾸는 일은 수집기가 한다. 예시 값은 특정인이 아닌 일반 예시로 둔다.

```toml
[run]
max_pages = 2
delay_sec = 2.0
max_cards_per_track = 30

[common]
education = "초대졸"            # 고졸 / 초대졸 / 대졸 / 석사 — 이 학력으로 지원 가능한 공고만
my_career_months = 36           # 경력 공고의 최소 요구 경력과 비교 (신입이면 0)
allow_locations = [             # 앞부분 일치. "경기 성남시" 는 성남시 전체
  "서울 강남구", "서울 서초구", "경기 성남시",
]
exclude_words = ["영업", "텔레마케팅", "강사"]
exclude_companies = []
exclude_employment = ["파견직", "프리랜서"]

[[track]]
name = "기구설계"
sites = ["saramin"]
keywords = ["기구설계", "장비설계"]
career = ["신입", "경력"]      # 경력 공고는 최소 요구 경력 ≤ my_career_months 만

[[track]]
name = "개발 전환"
sites = ["jobkorea"]
keywords = ["백엔드", "풀스택"]
career = ["신입"]              # 경력무관 포함
include_any = []                # 갈래별 추가 조건 (비우면 통과)
```

저장소 주인의 실제 값은 Secret 에만 넣는다 (이 문서와 저장소에 적지 않음).

### Actions 에 넣는 값
- Secret: `JOBCATCH_CONFIG` (검색 기준 TOML), `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `MAIL_TO`, `KAKAO_REST_KEY`(선택 — 없으면 통근 계산 없이 지역 목록만)

## 6. 동작

1. 갈래마다, 지정한 사이트마다, 키워드마다 검색 (최신 등록순, 최대 2페이지)
2. 같은 공고 합치기 (`source:job_id`), 어느 갈래에서 나왔는지 기록
3. 공통 필터: 지역 · 학력 · 경력 · 제외 단어/회사/고용형태. 결과는 통과 / 확인 필요 / 제외 세 가지
4. 보낸 기록과 비교해 새 공고 + 마감 임박 공고로 메일 작성 · 발송 → 기록 갱신
5. 발송 실패 시 기록을 갱신하지 않는다 (다음 날 다시 보냄)

사이트별 확인한 사실 (2026-11-22)
- 사람인: 기존 `jobcatch/saramin.py` 그대로. 학력은 조건 3번째 칸("대졸(4년)↑" 등), 경력은 2번째 칸("신입", "경력 3년↑", "신입·경력").
- 잡코리아: `https://www.jobkorea.co.kr/Search/?stext=<키워드>&tabType=recruit` 가 서버에서 카드 HTML 을 내려준다(`data-sentry-component="CardJob"`, 1페이지 25건). 동작 확인한 파라미터: `careerType=1`(신입), `ord=RegDtDesc`(최신순), `Page_No`. 공고 ID 는 링크의 `GI_Read/<번호>`. 카드에 광고(AD)가 섞인다. 지역 파라미터는 `local=I000` 이 먹지 않아 미확인 → 지역은 수집 후 필터로 거른다. 카드에 마감일 · 학력이 없을 때가 많다.

## 6-1. 근무지 · 통근 시간

설정 (`[common]` 에 추가):
```toml
home_address = "서울 중구 세종대로 110"   # 예시. 도로명 주소
commute_limit_min = 60      # 이내면 통과
commute_soft_min = 75       # limit~soft 는 "통근 확인" 표시로 남김, 넘으면 제외
max_detail_lookups = 60     # 한 번 실행에 상세 페이지를 읽을 최대 공고 수
```
Secret: `KAKAO_REST_KEY`. 키나 `home_address` 가 없으면 통근 계산을 건너뛰고 지역 목록만 쓴다.

동작:
1. 카드 단계에서는 `allow_locations` 에 나온 시 · 도(예: 서울 · 경기)가 아닌 것이 확실한 공고만 뺀다 (통근 계산을 켰을 때).
2. 새 공고 후보만, 상한 `max_detail_lookups` 까지, 요청 사이 `delay_sec` 대기하며 상세 페이지에서 근무지 주소를 읽는다.
   - 사람인: `https://www.saramin.co.kr/zf_user/jobs/view?rec_idx=<id>` 의 `.jv_location .address`
   - 잡코리아: `https://www.jobkorea.co.kr/Recruit/GI_Read/<id>` 의 "근무지주소" 칸. 잡코리아는 이때 마감일 · 학력도 보충한다.
3. 주소 → 좌표: `GET https://dapi.kakao.com/v2/local/search/address.json?query=<주소>` (건물명 · 층 등 괄호 뒤는 떼고), `documents[0].x/y`
4. 대중교통: `GET https://dapi.kakao.com/v2/routing/publictraffic?start_x=&start_y=&end_x=&end_y=` (x=경도), `status == "OK"` 이면 `routes[].properties.totalTime`(초)의 최솟값 → 분. 출발 시각 지정은 API에 없다.
5. 분 ≤ limit → 통과, ≤ soft → "통근 확인", 넘으면 제외. 주소 · 좌표 · 경로를 못 구하면 지역 목록 판정으로.
6. 카드에 `🚇 약 52분` 표시. 소요 시간은 따로 저장해 두지 않는다 (경로 결과 저장 관련 약관 미확인).
7. 카카오 쿼터 초과(HTTP 400, code -10) · 키 오류면 그날은 통근 계산을 멈추고 지역 목록으로, 메일 맨 위에 "⚠ 통근 시간 계산 실패" 경고.

## 7. 메일

- 제목: `[Job-Catch] 11/23(월) 새 공고 12건 · 마감임박 3건`
- 본문: 휴대폰 폭에 맞춘 HTML, 표 대신 카드. 마감 임박(7일 이내)을 맨 위에, 그다음 갈래별로.

```
┌ 마감 임박 ─────────────────┐
│ D-3 · (주)가나정밀  [사람인]   │
│ 반도체 장비 기구설계 (경력 3년↑) │
│ 경기 화성시 · 정규직 · 초대졸↑  │
│ [공고 보기 →]                  │
└──────────────────────────┘
■ 기구설계 (5건)  ...카드
■ 개발 전환 (7건) ...카드
```

- 마감 임박에는 예전에 보낸 공고도 다시 넣는다. 같은 공고는 메일에 한 번만 (마감 임박 쪽에).
- 갈래당 카드 `max_cards_per_track`(기본 30)장까지, 넘으면 "외 N건". 첫 실행도 같은 규칙으로 평소처럼 보낸다.
- 새 공고 0건인 날도 "새 공고 없음" 짧은 메일 (돌았다는 확인용)
- 한 사이트가 0건이거나 응답 오류면 메일 맨 위에 "⚠ 잡코리아 수집 실패" 경고
- 학력 · 마감 · 지역을 확정 못 한 공고는 빼지 않고 "학력 확인" · "지역 확인"처럼 표시
  - 지역 확인 대상: 시 · 구 없이 "서울" · "경기"만, 여러 지역 중 허용 지역이 하나라도 있음, "전국" · "재택", 지역 칸 비어 있음. 허용 목록 밖이 확실한 공고만 뺀다.
- 꼬리말: 출처 표기 (사람인 · 잡코리아), 원문 링크에서 확인 안내

## 8. 실행 (GitHub Actions)

- `.github/workflows/daily.yml`, `cron: "30 21 * * *"` (UTC 21:30 = KST 06:30; 예약 실행은 늦어질 수 있어 30분 당겨 둠). 수동 실행(`workflow_dispatch`)도 둔다.
- **보낸 기록은 저장소에 커밋하지 않는다.** 공개 저장소에 올리면 어떤 공고를 받는지(=직무 · 지역)가 드러난다. 대신 Actions 캐시에 둔다: 실행마다 `seen-<run_id>` 키로 저장, `seen-` 접두어로 가장 최근 것을 복원. 캐시를 잃으면 한 번 다시 보내게 될 뿐이다 (카드 상한으로 양 제한).
- 기록 내용: 공고마다 제목 · 회사 · 링크 · 마감일 · 처음 보낸 날 (마감 임박 재알림용). 마감 지나고 30일 뒤 정리.
- **공개 로그에는 건수만 찍는다.** 키워드 · 회사 · 제목 · 설정 내용은 로그에 쓰지 않는다.
- 로컬 실행: `python run.py --dry-run` 은 메일 대신 `output/` 에 HTML 저장, 기록은 `data/` (둘 다 `.gitignore`).
- 같은 설계로 PC 작업 스케줄러에서도 돌 수 있지만 그 설정은 이번 범위 밖.

## 9. 다른 사람이 쓰는 법 (README 에 추가)

1. 저장소 fork
2. Gmail 앱 비밀번호 만들기 (2단계 인증 필요)
3. 내 저장소 Settings → Secrets and variables → Actions 에 Secret 4개(카카오 키를 쓰면 5개) 등록
4. Actions 탭에서 워크플로 켜기 (fork 는 예약 실행이 기본으로 꺼져 있음) → 수동 실행으로 시험

## 10. 만드는 사람에게 맡기는 것
